# CareerOS design

CareerOS serves candidates managing resumes, applications and interviews. Start from the candidate's job or document and keep its state visible through the next action.

| Decision | Standard |
| --- | --- |
| Public pages | Warm paper background, Instrument Serif display, Manrope body and actual product output. Use one primary entry action and plain descriptions of current workflows. |
| Workspace | Quiet canvas, compact navigation, ruled lists and readable row labels. Show the job title first and make each application link open its details. |
| Mobile web | Keep Overview, Resumes and Applications visible. The drawer provides secondary destinations, outside content is inert when open, and the closed drawer is hidden from keyboard navigation. |
| Colour | Paper #f4f3ed, ink #18352b, rule #d9dfd7, focus #316943. Existing feature tokens continue to provide state colours and form styling. |
| Data | Explain browser storage at entry and in Settings. Leave local and cloud actions clearly differentiated. Use fictional or empty records for design validation. |
| Motion | Honour reduced motion. Transitions communicate location and state. |

The Linear design study informed list structure and quiet separators. Mobbin's LinkedIn iOS job tracker informed the prominence of Applications on mobile web. Use the shared component and registry workflow in the root instructions for new controls.
