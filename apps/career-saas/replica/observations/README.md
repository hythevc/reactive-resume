# REA observations and component reconstruction

Observed on 8 November 2026 with REA 6.8.0, using the installed `reverse-engineer-anything` skill and its browser-runtime workflow. The first CareerOS build used public-page research; it did not use REA to observe competitors. This subsequent pass adds actual REA browser observations and changes grounded in them.

Thirteen competitors were attempted. Twelve rendered public pages or product previews; Jobscan returned an upstream connection error. MeetDex is the thirteenth source and includes two verified public-demo interactions plus an unauthenticated entry screen. This is selected market research, not complete observation or full parity with the competitors' authenticated SaaS products. No competitor account was created, no document/photo was uploaded, and no application, email or payment was submitted.

REA called `capture_browser_scenario` and `capture_web_screenshot` through its actual local MCP server. Public captures used accessibility and pixels; no network bodies, private API replay or script-source analysis was used. Initial direct launches could not navigate through the host proxy; successful observations connected to owned proxy-configured Chromium instances over literal loopback CDP, with TLS verification enabled. Service workers were explicitly allowed where required by REA. Owned browsers were closed afterward.

Some captures have a padded screenshot canvas because CDP emulation did not resize the native browser. Those images establish content, not computed CSS measurements. Several overall completeness records report missing events because events were intentionally not captured; they are not equality-eligible or proof of full application coverage. Failed actions and inaccessible surfaces remain in the indexes rather than being scored as observed successes.

## Current product boundary

These local improvements do not connect model providers, cloud accounts, paid billing, job feeds/submission, recruiter discovery or email delivery. The broader production gaps remain in [the feature matrix](../features.csv) and [parity report](../parity.md).

The MeetDex source observations establish public behavior; they do not establish that CareerOS's role-discovery flow has passed the same browser checks.
