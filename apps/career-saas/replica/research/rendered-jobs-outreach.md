# Jobs and outreach: actual rendered REA observation

Observed 8 November 2026 using `/workspace/tools/bin/rea mcp` and its actual advertised input schemas (saved as `actual-mcp-schemas-full.json`). This supplements the earlier extracted public-page research. It is not inspection of authenticated SaaS products.

## Capture method and boundaries

REA `capture_browser_scenario` attached to a separate, temporary-profile Chromium via loopback CDP port 9335. Chromium used the inherited HTTPS proxy with TLS verification enabled. Capture requested URL, accessibility text and viewport screenshots only. All event families, network bodies, header values, DOM-source capture and script-source capture were disabled. No accounts were created, no login occurred, no forms were submitted, no emails were sent, and no private APIs or bundles were collected.

The first REA launch-mode request failed during navigation, with cleanup confirming the owned process terminated; retained in `loopcv.mcp.json`. Changed setup to a proxy-configured Chromium rather than retrying unchanged. An initial attached capture produced content in a default 800px browser window, despite a 1440px capture viewport. Relaunching our browser with `--window-size=1440,1000` fixed this; `loopcv-home.png` and later screenshots show the intended desktop width. REA connect mode used `environment.service_workers=allow` because existing workers can otherwise prevent attachment. This permits observation; it does not inspect service-worker code.

`evidence-index.json` records exact evidence IDs, capture completeness, step outcomes and screenshot filenames. Each `.request.json` records actual submitted tool arguments; each `.mcp.json` retains the actual MCP response. Requested URL/accessibility/screenshot artifacts were captured for all five vendors. REA marks those records `incomplete` and `equality_eligible=false` because the events section was intentionally omitted; this pass does not establish telemetry equality or complete runtime coverage. These record what the public page rendered, including its marketing claims; they do not validate those claims.

## Concrete component comparison and local implementation decision

Before-source snapshots are `before-jobs.tsx` and `before-outreach.tsx`; they were copied from our own implementation before these observations informed changes. Competitor screenshots are retained as research evidence only and are not app assets.

| Our component before                                                                                                                                                 | Relevant observed public pattern                                                                                                                              | Implementable change                                                                                                                                                                                                                                                        |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `JobsView.prepareMatches`: only saved state, nonempty description and score threshold determine eligibility. No company exclusions or location criteria are applied. | LoopCV exclusion page explicitly describes per-search company exclusion; home names location preferences and manual review.                                   | Persist excluded company names and permitted location terms. Use one shared eligibility helper both in the table and the atomic preparation operation, so the explanation cannot disagree with the action. High-scoring excluded companies must stay Saved.                 |
| Jobs table shows only numeric match and stage. Draft tab exists but has no explanation of why a saved job cannot enter it.                                           | LoopCV separates matching, filtering and one-click review; Simplify distinguishes assisted/automated workflows and tracking.                                  | Show each saved job's preparation reason: excluded company, missing description, location mismatch, below threshold, or eligible. Keep Draft as an explicit review queue and preserve local-only submission disclosure.                                                     |
| `OutreachView` stores name/company/role/email/message only; template says it is interested in the company but has no reason or source field.                         | NetworkAI public screenshot and text use target/context input beside an editable draft. Hunter shows source/verification as separate from the contact itself. | Add optional safe HTTPS source URL and user-entered contextual reason. Put that supplied context into drafts only on explicit create/refresh; preserve edited drafts when contact metadata changes. State that source is user supplied and this app has not verified email. |
| Current mailto opens a user's email app, with manual Contacted/Replied stages.                                                                                       | NetworkAI separates finding/drafting from outreach; Hunter separately labels verification and engagement.                                                     | Retain clear manual status semantics. Do not add a verified badge, pretend send receipt or claim automated outreach.                                                                                                                                                        |

These changes transfer publicly observable functional ideas into our original local app. They do not reproduce competitors' logos, screenshots, copy, fonts or private code. After-source and verification evidence will be appended when changes finish; production AI, job delivery, verified contact discovery and email sending remain gaps.

## Not measured

No authenticated funnel, actual recruiter network, private API, delivery confirmation, model quality, visual-parity score, app-store binary or native app was inspected. Public vendor outcome multipliers and guarantees are not adopted. Only the current desktop public pages were captured in this observation pass; existing mobile QA of our app is a separate artifact.

## Implemented changes and verification

After-source snapshots: `after-jobs.tsx` and `after-outreach.tsx`. The implementation now stores exclusions and location criteria, displays preparation eligibility reasons beside each job, uses the same tested domain helper inside preparation, exposes a Draft review queue, and preserves its local daily limit atomically. Outreach now stores a safe optional HTTPS source and up to 5,000 characters of factual context, shows the unverified/source disclosure, and includes context only when creating or explicitly refreshing a draft. Metadata edits keep an existing edited draft. No real AI, job submission, discovery, verification or email integration was added.

Validation: full app TypeScript check passed; all 12 domain tests passed. An isolated local Playwright context tested the browser workflow and recorded `local-improvements-test.log`: a high-matching Forma role remained Saved when case-insensitively excluded; a daily limit of one allowed one transition and blocked a second; the Draft queue contained exactly the prior and newly prepared draft; source URL persisted; supplied context entered a new draft; metadata edits preserved a manual draft; explicit refresh included updated context; contact status stayed Draft. This local app test used Playwright over our own browser CDP connection, not competitor inspection.

Rendered after screenshots: `careeros-jobs-after-root-normalized_result-steps-1-artifacts-screenshot-value.png` was captured through actual REA, while `local-draft-queue-tested.png` and `local-outreach-source-tested.png` were captured by the local functional test and visually inspected. Competitor screenshots were also inspected with view_image. No claim of pixel parity is made; the transferable behavior was exclusions plus explicit review, and sourced context plus editable drafts.
